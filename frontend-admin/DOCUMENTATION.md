# Musica Profile — документация

Версия **0.4.3**. Обзор проекта и запуск через Docker — в [корневом README](../README.ru-RU.md).

Самостоятельный frontend админки на Svelte 5, TypeScript strict и Vite.
Светлый интерфейс с русским и английским языками, входом через общую сессию
Musica и отдельными страницами аккаунта, пользователей и хранилища.
Пользователи и хранилище доступны только администраторам.

## Авторизация и переходы

Вход и регистрация находятся только в этом интерфейсе. Плеер передаёт
`return_to` с текущим плейлистом; после входа профиль возвращает пользователя
по проверенному адресу. Прямое открытие `/profile/` оставляет пользователя в профиле.
Логотип переводит обратно в плеер, меню круглой аватарки содержит выход.

`GET /api/capabilities` определяет доступность регистрации. Если
`registration_enabled:false` или возможности сервера не удалось получить,
кнопка регистрации скрыта. Начальный ответ 401 проверки сессии означает,
что нужно войти, и не выводится как ошибка позади формы.
Сессия хранится в HttpOnly cookie; пароли и токены не передаются в URL.

## Запуск

Из `frontend-admin/`:

```sh
npm ci
npm run dev
```

Профиль открывается на <http://localhost:5174/profile/>, плеер — на порту `5173`.
Vite проксирует `/api/` на `http://127.0.0.1:8080`, сохраняя исходный Host.
Для входа и операций нужен актуальный backend и настроенные PostgreSQL/MinIO.
Администратор создаётся через `BOOTSTRAP_ADMIN_USERNAME` и
`BOOTSTRAP_ADMIN_PASSWORD`; обычные пользователи тоже могут управлять своим аккаунтом.

В PowerShell при запрете `npm.ps1` используйте `npm.cmd`.

Логотип возвращает в плеер: в dev — на текущем хосте, порт `5173`;
в production — `/`. Для другого адреса плеера задайте
`VITE_PLAYER_URL` по [.env.example](.env.example) перед сборкой.

## Структура и стиль

```text
src/app/             Сборка приложения, context, состояния и порядок CSS
src/pages/           Компоновка страниц
src/features/        Авторизация, профиль, пользователи и хранилище
src/shared/          Независимые переводы, компоненты, стили и утилиты
public/              Статические ресурсы
tests/               Проверки локализации и входных данных API
```

Правила из [AGENTS.md](../AGENTS.md) общие для обоих frontend: Svelte 5 runes,
краткий русский JSDoc, логические отступы и многострочный CSS. Для новых фич
используйте `model.ts`, `api.ts`, `state.svelte.ts` и `ui/` по необходимости.
Исходники плеера не импортируются в профиль. Язык общий с плеером: localStorage
`musica:locale` и несекретная cookie `musica_locale` синхронизируют вкладки и dev-порты
на одном хосте. Данные учётной записи там не хранятся. Раздел сохраняется в URL
`?page=profile|users|storage`, поэтому перезагрузка и история браузера сохраняют навигацию.

## Проверка и сборка

```sh
npm run build
npm run format:check
npm run test:i18n
npm run test:models
npm run test:navigation
npm run preview
```

Сборка включает `svelte-check`; результат находится в `dist/`.
Preview работает на <http://localhost:4174/profile/> и не проксирует API.
Для production используйте один HTTPS-домен: плеер `/`, профиль `/profile/`,
reverse proxy для `/api/`. Вход и регистрация находятся только в профиле;
`return_to` разрешает возврат только внутрь настроенного адреса плеера.
Cookie сессии — HttpOnly; роль и полномочия
проверяются backend при каждом запросе.
Service worker в админке не регистрируется.
Готовая конфигурация nginx для `/profile/` включена в корневой Compose.

Браузерный сценарий входа/регистрации и возврата с общей cookie проверяется
из `frontend-app/` командой `npm run test:auth-ui`; оба dev-сервера должны работать.
Проверка использует тестовый API и не меняет пользовательскую БД.
Меню, мобильные отступы, общий язык, сохранение разделов и скрытую регистрацию
проверяет `npm run test:profile-ui` из того же подпроекта.

## Операции

- Аккаунт: смена пароля с отзывом всех сессий, выбор языка, удаление аккаунта
  с подтверждением текущим паролем. Личные треки удаляются, сервисные сохраняются.
- Пользователи: список обычных аккаунтов, создание и подтверждённое удаление.
  Системная учётка скрыта; свой аккаунт администратор удаляет через настройки профиля.
- Хранилище: графики объёма зарегистрированных аудиоисходников и orphaned-треков,
  счётчики HLS, ожидающих загрузок и задач S3. Это не полный размер MinIO:
  изображения, HLS и ожидающие очистки файлы в байтовую сумму не входят.
  Диаграмма разделяет личные исходники, используемые общие исходники и orphaned.
  Размеры показываются отдельно от количества треков. В ожидание загрузки
  не включаются треки с failed-задачами скачивания или загрузки.
- Удаление orphaned-треков: ручная очистка всех найденных кандидатов. Активные треки
  пропускаются. Физическую очистку S3 выполняют существующие jobs и worker.

При удалении аккаунта активная загрузка или подготовка личного трека приводит
к `409`; транзакция откатывается целиком, можно повторить после завершения обработки.

## API

| Операция | Маршрут |
| --- | --- |
| Возможности сервера | `GET /api/capabilities` |
| Текущий профиль | `GET /api/users/me` |
| Вход, регистрация, выход | `POST /api/auth/login`, `/api/auth/register`, `/api/auth/logout` |
| Смена пароля | `PUT /api/profile/password` |
| Удаление аккаунта | `DELETE /api/profile` |
| Список и создание пользователей | `GET /api/admin/users`, `POST /api/admin/users` |
| Удаление пользователя | `DELETE /api/admin/users/:id` |
| Статистика хранилища | `GET /api/admin/storage` |
| Очистка неиспользуемых общих треков | `POST /api/admin/storage/cleanup-orphaned` |

Форматы запросов, права доступа и ограничения описаны в
[документации backend](../backend/DOCUMENTATION.md#профиль-и-административный-api).
