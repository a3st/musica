# Frontend Musica

Svelte 5, TypeScript strict, Vite, PWA. Интерфейс работает с настоящим API
по относительным URL `/api/`; демонстрационных треков в приложении нет.

## Запуск

Сначала настройте backend, PostgreSQL, MinIO и вручную примените `001_init.sql`
к пустой БД по [инструкции backend](../backend/README.md). Для воспроизведения включите HLS-воркер
и установите FFmpeg на backend либо используйте Docker-образ.

Из `frontend/`:

```sh
npm ci
npm run dev
```

В PowerShell при запрете `npm.ps1` используйте `npm.cmd`.
Откройте <http://localhost:5173>. Vite проксирует `/api` на `127.0.0.1:8080`.
Прокси сохраняет исходный `Host` (`changeOrigin: false`), чтобы он совпадал
с браузерным `Origin` при проверке изменяющих cookie-запросов на backend.
Вход и регистрация создают HttpOnly cookie-сессию; токен не сохраняется
в localStorage и не добавляется в URL аудио.
Пока пользователь не авторизован, открытую форму входа нельзя закрыть
кликом вне окна или клавишей Escape; кнопка закрытия скрыта.
После успешного входа или регистрации форма закрывается автоматически.
За формой входа отображается декоративная заглушка с размытием,
без данных медиатеки и доступных для взаимодействия элементов.
После входа открывается Uploads. Отдельного начального экрана нет:
во время загрузки показывается индикатор, при ошибке — кнопка повтора.

## Организация кода

```text
src/
  main.ts                     Монтирование Svelte-приложения
  app/
    App.svelte                Жизненный цикл приложения, диалоги и уведомления
    state.svelte.ts           Композиция состояний и операций фич
    context.ts                Типизированный контекст приложения
    navigation.ts             Открытие плейлистов и общих ссылок
    menus.ts                  Действия контекстных меню
    styles.css                Порядок подключения CSS
    layout/                   Верхняя и боковая панели, раскладка
  pages/                      Экран открытого плейлиста
  features/
    auth/                     Сессия и форма входа
    playlists/                Список, детали, обложки и редактирование
    tracks/                   Модель, API и таблица треков
    player/                   Audio/HLS движок, управление и очередь
    uploads/                  Загрузка файлов и её прогресс
    spotify-import/           Парсер JSON и отправка метаданных для загрузки
  shared/
    api/                      HTTP-клиент, ошибки и валидация ответов
    i18n/                     Переводы ru-RU/en-US и выбор языка
    theme/                    Выбор и сохранение темы
    styles/                   Переменные тем и базовые правила
    ui/                       Диалог, иконки, меню и скроллбар
    utils/                    Хранилище настроек, буфер обмена и форматирование
tests/
  unit/                       Парсер Spotify и движок плеера
  integration/                Проверка Vite-прокси
  e2e/                        Интерфейс и production PWA
  helpers/                    Загрузка TypeScript для тестов
```

В каждой фиче `model.ts` описывает данные и проверяет входящий JSON,
`api.ts` выполняет запросы, `state.svelte.ts` управляет операциями и реактивным
состоянием, а `ui/` содержит Svelte-компоненты. Небольшие фичи содержат только
нужные им части. Компоненты получают состояние и действия через props;
композиция страниц использует типизированный context из `app/`.
Общие модули в `shared/` не зависят от фич.

Состояние создаётся на время жизни приложения с помощью runes Svelte 5.
Смена плейлиста, темы или языка не пересоздаёт плеер. `features/player/engine.ts`
управляет Audio/HLS отдельно от разметки, а `state.svelte.ts` передаёт его
снимок компонентам. При закрытии приложения освобождаются таймеры, слушатели,
HLS и активные загрузки; запоздалые ответы отменённых операций игнорируются.

CSS записан многострочными блоками. Стили панели или фичи лежат рядом
с соответствующими компонентами в `*.css`; общие переменные находятся
в `shared/styles/tokens.css`, базовые правила — в `base.css`.
`app/styles.css` задаёт порядок их подключения. Небольшие независимые
компоненты, например контекстное меню, используют scoped `<style>`.
Для форматирования TypeScript, Svelte и CSS используйте `npm run format`.

Переводы находятся в двух явных словарях `shared/i18n/locales/ru-RU.ts`
и `en-US.ts`. В коде используйте стабильный ключ вместо русской фразы:

```ts
language.t('uploads.title');
language.t('tracks.play', { title: track.title });
```

Ключи группируются по назначению: `common`, `auth`, `playlists`, `tracks`,
`player`, `uploads`, `spotify` и другие. TypeScript проверяет ключи и
именованные параметры, например `{title}` или `{count}`, а также полноту
английского словаря. `npm run test:i18n` проверяет совпадение параметров
в обоих языках и подстановку пользовательских данных.

## Интерфейс

Две темы с синим акцентом: тёмная и светлая. Меню профиля в верхней панели
содержит переключение темы, языка (`ru-RU`, `en-US`) и выход. Тема и язык
сохраняются на устройстве; язык меняется без перезагрузки и остановки плеера.
Переводятся интерфейс и сообщения, а пользовательские названия остаются как есть.
В боковой панели есть отдельный поиск плейлистов,
вверху — поиск треков, загрузка и профиль; снизу — компактный плеер.
Плейлист показывает крупную обложку, автора, количество треков и строки
с миниатюрами. Если картинки нет, используется абстрактная заглушка.
Длительность пока показана как `— ч прослушивания`: API ещё не возвращает
продолжительность треков. Это заглушка общей длительности плейлиста.
Ширину боковой панели можно менять за правый край (80–340 px): в узком
варианте остаются обложки. Поддерживаются стрелки, Home/End и сохранение ширины.
Панель занимает всю высоту до плеера; её полоса прокрутки скрывается в покое.
Панели имеют закруглённые края. WEB пока недоступен.
Верхний бар с логотипом musica занимает всю ширину; под ним рядом находятся
библиотека и плейлист, а нижний плеер также занимает всю ширину.
В шапке профиль представлен аватаркой с меню, без имени и подписи медиатеки.
Таблица использует исполнителя и статус из текущего API; колонка после
исполнителя показывает `—:—`, пока backend не возвращает длину трека.
Иконки PWA соответствуют новому логотипу. Их можно пересоздать из `public/icon.svg`
командой `node scripts/icons.mjs` (нужен Chromium или Microsoft Edge, как для UI-тестов).

- На ПК слева находится список собственных и общих плейлистов. На мобильном
  его открывает кнопка библиотеки рядом с поиском.
- Поиск фильтрует текущий плейлист по названию и исполнителю.
- Плеер снизу показывает обложку текущего плейлиста, название и исполнителя.
  Когда трек не выбран, блок с обложкой и метаданными скрыт.
  Есть пауза, следующий/предыдущий трек, перемотка; на ПК также громкость,
  случайный порядок и повтор. Пробел управляет воспроизведением вне форм.
  Клик по значку громкости отключает и возвращает звук, сохраняя уровень.
  При мьюте ползунок и заполнение полосы уходят в ноль, при включении звука
  возвращаются к прежнему уровню.
  Ползунок перемотки виден при наведении, перетаскивании или фокусе с клавиатуры.
  Кнопка очереди рядом открывает отдельную колонку справа с текущим и
  следующими треками: их можно воспроизводить и убирать из очереди.
  Она сужает плейлист; на мобильном обе панели делят центральную область
  по высоте. Очередь не перекрывает плейлист, шапку и плеер.
  В открытом плейлисте остаются кнопки Play и Shuffle; меню плейлиста
  доступно по ПКМ. Главная прокрутка использует узкий ползунок до 80 px,
  поддерживает перетаскивание, колёсико и клавиши Home/End/Page Up/Page Down.
- Кнопка загрузки доступна на ПК. Можно выбрать несколько файлов или
  перетащить их в окно, поправить название и исполнителя.
  Треки загружаются только в `Uploads`; добавить их в другой плейлист можно
  через меню трека. Импорт из Spotify открывается из окна загрузки.
  На мобильном окно загрузки можно открыть из панели библиотеки.
  Лимит клиента — 64 MiB на файл,
  до 50 файлов в очереди. Backend может установить меньший лимит.
- Для каждого файла выполняются создание трека, PUT файла и подготовка HLS.
  Есть прогресс, отмена текущей загрузки и повтор ошибки. Можно закрыть окно:
  очередь продолжит работать, пока открыта вкладка. Перезагрузка страницы
  сбрасывает очередь; незавершённые записи остаются в `Uploads` для удаления.
- Меню трека открывается по ПКМ на строке или кнопке «…». Оно позволяет
  воспроизвести трек, поставить следующим, добавить в очередь или в другой доступный для записи плейлист
  и удалить. Из `Uploads` удаляется запись, все связи, оригинал и опубликованный
  HLS; из обычного плейлиста — только связь. Перед удалением показано подтверждение.
  Во время подготовки HLS backend отклоняет полное удаление с `409`.
- Плейлист можно создать с названием, описанием и видимостью. Общие плейлисты
  отображаются с учётом роли; viewer не может менять состав.
  В форме можно выбрать или перетащить обложку PNG/JPEG/WebP до 5 MiB.
  Она отправляется отдельным PUT после создания плейлиста. Если загрузка
  обложки не удалась, повторное сохранение использует уже созданный плейлист.
  ПКМ на плейлисте открывает редактирование и удаление.
  Обновление сохраняет существующие теги; удаление доступно владельцу и
  сохраняет треки в Uploads. Дефолтный плейлист удалить нельзя.

Safari использует нативный HLS, остальные поддерживаемые браузеры — `hls.js`,
загружаемый при первом воспроизведении. Приватные запросы манифеста и сегментов
авторизуются cookie-сессией. Если autoplay заблокирован, нажмите кнопку плеера.
Прослушивание без сети пока недоступно.

## Production и PWA

```sh
npm run build
npm run preview
```

Результат — `dist/`. Для production разместите его в корне домена за HTTPS
и проксируйте `/api/` к backend на том же домене. Передавайте исходный `Host`
и задайте backend `AUTH_COOKIE_SECURE=true`. `preview` нужен только для проверки
сборки; для API в этом режиме нужен reverse proxy.

Service worker кеширует оболочку, включая код HLS-клиента, но не API,
обложки из API или аудио. Обновление применяется по кнопке; активная загрузка
откладывает его. В dev service worker отключён. Манифест позволяет установить
приложение на домашний экран/рабочий стол.

## Импорт Spotify

Кнопка **Импорт из Spotify** находится в окне загрузки треков.
Выберите `Playlists.json`, `YourLibrary.json` или оба файла из выгрузки аккаунта Spotify.
До отправки отображается количество уникальных треков и плейлистов. Подкасты и
локальные файлы пропускаются; неверный JSON и метаданные показывают ошибку.

Плейлисты создаются приватными, все треки попадают также в Uploads. Совпадения по
Spotify URI объединяются в рамках одного импорта; без URI используется название
и исполнитель. На backend треки переиспользуются между пользователями через
общую фичу `web_int`, а загрузки хранятся в `jobs`. Повторная отправка JSON
повторяет неудачные загрузки без дублирования треков. Скачивание продолжается
на сервере после закрытия окна. Отдельная история и общий прогресс импорта
не сохраняются; состояние треков отображается в плейлистах. Поиск по названию и исполнителю
может подобрать другую версию композиции. Обложка встраивается в MP3,
а интерфейс плеера пока показывает обложку плейлиста.
После смены обложки изображение обновляется в плейлисте, боковом меню и плеере
без перезагрузки страницы. Адрес изображения содержит версию из `image_key`.
Выбранный плейлист сохраняется в URL (`?playlist=...`); перезагрузка открывает
тот же плейлист. Для доступа по ссылке сохраняется `#share=...`.

Контекстные меню плейлистов и треков открываются правой кнопкой мыши;
меню трека также доступно через «…». Действия разделены на группы с иконками.
Повторное нажатие на «…» закрывает меню. Добавление в другой плейлист открывает
соседнее подменю по наведению, нажатию или стрелке вправо; у края экрана оно
появляется слева, на узких экранах — под основным меню. Стрелка влево и Escape
возвращают в основное меню. Свернутая боковая панель имеет минимальную ширину 104 px.
У Uploads защищены название, описание, обложка и настройки доступа;
добавление и удаление треков остаются доступны.

«Копировать ссылку» доступно для публичного плейлиста и владельцу плейлиста
с доступом по ссылке. Приватность при копировании не меняется.
Ссылка открывает плейлист в приложении, в том числе без входа в аккаунт;
для воспроизведения по ссылке используются разрешения HLS API.
Токен находится во фрагменте URL и не отправляется с загрузкой оболочки.
Первое копирование ссылки unlisted создаёт новый токен и отзывает предыдущую
ссылку по контракту backend. До перезагрузки страницы повторное копирование
использует тот же токен; изменение настроек плейлиста сбрасывает его.
Для гостя unlisted-плейлиста отображается стандартная обложка:
текущий API обложек не принимает токен общего доступа.

## Проверки

```sh
npm run check
npm run format:check
npm run test:player
npm run test:i18n
npm run test:spotify
npm run build
npm run test:proxy
# В другом терминале уже запущен npm run dev:
npm run test:ui
# После сборки, в другом терминале запущен npm run preview:
npm run test:pwa
```

Браузерные тесты используют Playwright и изолированный API из фикстур,
пользовательская БД не затрагивается. FFmpeg должен быть в PATH или указан
через `FFMPEG_PATH`: он генерирует настоящее аудио для проверки HLS.
На Windows автоматически используется установленный Microsoft Edge.
На остальных системах установите Chromium командой `npx playwright install chromium`
либо задайте путь через `CHROMIUM_PATH`. `UI_TEST_URL` меняет адрес тестируемого
frontend, по умолчанию `http://127.0.0.1:5173`.
`test:pwa` по умолчанию обращается к `http://127.0.0.1:4173` и проверяет
production service worker, содержимое кеша и открытие оболочки без сети.
`test:proxy` запускает настоящий Vite-прокси с временным HTTP-приёмником
и проверяет передачу Host/Origin/cookie для создания плейлиста и загрузки;
работающий backend и браузер для него не нужны.

Проверяются размеры ПК/мобильного, поиск, безопасный вывод метаданных,
воспроизведение, очередь загрузки, создание плейлиста, вход и оба удаления.
Скриншоты сохраняются в игнорируемый `backend/.zig-cache/`.

`test:player` проверяет очередь, удаление треков, громкость, перемотку,
прерывание подготовки HLS, повторный запуск после прерванного `play()`
и освобождение слушателей без браузера. Кнопки в строке текущего трека,
в заголовке плейлиста и в нижней панели синхронно переключают play/pause,
сохраняя позицию воспроизведения; текущая строка выделяется цветом.
`test:spotify` проверяет парсинг, валидацию и объединение треков из JSON.
